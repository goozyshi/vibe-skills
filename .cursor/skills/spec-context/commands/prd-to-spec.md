# /prd-to-spec

将用户口述或 PRD 内容转为结构化 spec。

## 输入方式

1. **聊天输入**：用户在对话中口述或粘贴需求文本。
2. **指定文件**：`/prd-to-spec path/to/prd.md`，读取文件内容。

不支持 URL 抓取。

## 步骤

### 1. 获取输入

- 聊天输入 → 直接使用用户消息内容。
- 文件路径 → 读取文件。
- 输入超过 200 行 → 先提取摘要和功能点清单，用户确认后再继续。

完成标志：获取到可处理的需求文本。

### 2. 提取要点

从输入中提取：
- 标题、一句话摘要
- 功能点列表（动词开头，一行一条）
- 验收标准列表（可验证，一行一条）
- 关联文件（推断或用户指定）
- 关键词
- 平台差异（如有）

**硬规则**：只提取用户明确提到的内容，不添加推测。关键缺失信息放入"待确认"章节并询问用户。

### 3. 生成 spec ID

格式：`REQ-{模块}-{序号}`。
- 模块名从需求内容推断（如 order、auth、home）。
- 序号从 `specs/active/` 已有 spec 中取最大值 +1。无已有 spec 则从 001 开始。

### 4. 填充模板

读取 [spec-template.md](../references/spec-template.md)，填充 frontmatter 和内容章节。

- `status: active`
- `progress: 0`
- `updated`: 当天日期
- `prd_link`: 若用户提供了外部链接则填入

### 5. 保存并更新索引

- 文件保存到 `specs/active/{模块}/{spec-id}.md`。模块目录不存在则创建。
- 运行 `node specs/scripts/generate-spec-index.js` 更新索引。

### 6. 确认

向用户展示生成的 spec，询问是否需要修改。标记待确认项。

完成标志：spec 文件已保存，索引已更新，用户已确认或标记了待修改项。
