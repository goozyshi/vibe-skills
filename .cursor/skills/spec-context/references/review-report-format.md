# Review 报告格式

`/review` 完成后按此格式输出报告。

---

```markdown
## Code Review 报告

### 需求摘要

- Spec: {id} {title}
- 变更: 一句话描述本次代码变更
- 迭代: 第 {n} 次（共 {total} 次）

### 代码变更

- {文件路径}: 变更描述

### 验收标准检查

| # | 验收标准 | 状态 | 说明 |
|---|----------|------|------|
| 1 | 标准描述 | ✅ 通过 / ❌ 未实现 / ⚠️ 部分实现 | 具体说明 |

### 问题列表

- [阻塞] 描述（验收标准未实现或可能导致线上异常）
- [警告] 描述（有风险但不阻塞）
- [建议] 描述（优化项）

### 结论

- 通过 / 不通过：原因说明。
```

## 问题分级规则

| 级别 | 判定条件 | 处理 |
|------|----------|------|
| `[阻塞]` | 验收标准未实现；可能导致线上异常 | 必须修复 |
| `[警告]` | 缺少边界/异常处理；缺少 loading 态 | 建议修复，不阻塞 |
| `[建议]` | 命名、代码风格、性能优化 | 可延后 |

## 与外部 skill 的级别映射

外部 skill（如 code-reviewer）返回 P0-P3 级别时：

`P0/P1 → 阻塞，P2 → 警告，P3 → 建议`
