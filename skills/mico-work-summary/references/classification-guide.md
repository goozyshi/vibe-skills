# 工作主题提炼方法论

将用户描述的具体工作事项提炼为有业务价值的工作主题。不同业务、不同工种的主题差异极大，无法穷举固定分类。遵循以下推理路径，在任何业务场景下都能引导用户提炼出恰当的主题。

## 主题提炼目标

将碎片化的工作归纳到业务语境中，让读者（业务协同方和管理者）一眼看出工作的业务意义。直接罗列任务（如"修了3个bug、写了2个接口"）对读者毫无价值。

---

## 分层理解执行步骤

提炼主题前，从三个层次建立理解，每一层为下一层提供推理依据。

### 步骤1：提取业务域特征

**执行**：
1. 从用户输入中提取业务名称（如"MicoWorld"）
2. 检查业务知识库 `business-knowledge.md` 是否已有该业务记录
3. 若有记录，读取业务类型、核心特性、历史主题
4. 若无记录，询问用户：
   - "这个业务是什么类型？"（如：出海社交视频直播App）
   - "核心业务模式是什么？"（如：通过虚拟礼物和会员变现）
   - "主要服务什么用户群？"（如：海外年轻用户）

**输出**：业务域特征描述（类型+模式+用户群）

### 步骤2：识别用户角色与动作

**执行**：
1. 从用户描述中识别工种（开发/产品/运营/设计等）
2. 提取具体动作（开发版本、设计方案、分析数据等）
3. 判断这些信息是否足够推断业务目标：
   - 产品/运营通常直接说明业务目标 → 进入步骤3
   - 开发说"做了V2.19.0版本" → 追问"这个版本解决什么业务问题？"

**输出**：用户角色 + 动作 + 业务目标（确认或待确认）

### 步骤3：推断并确认主题

**执行**：
1. 基于"业务域特征 × 用户动作"推断2-3个候选主题方向
2. 向用户展示候选主题，附带简要解释：
   ```
   根据"直播间礼物动效"，可能属于：
   1. 商业化变现 - 提升礼物转化率（如果目标是增加收入）
   2. 用户体验优化 - 增强互动反馈（如果目标是改善体验）
   3. 技术能力建设 - 动效渲染性能（如果目标是解决性能问题）
   
   请选择最符合本周工作重点的主题，或补充说明实际目标。
   ```
3. 用户确认后，确定最终主题

**输出**：确定的工作主题

## 动作+对象提取步骤

从用户的自然语言描述中提取主题的具体操作方法。

### 步骤1：识别动作和对象

**执行**：从用户描述中提取：
- **动作**：开发、优化、修复、设计、搭建、迁移、重构...
- **对象**：礼物系统、推荐算法、支付流程、直播间...

### 步骤2：结合业务域推断业务意图

**执行**：将"动作+对象"放到业务域语境中理解：
- 同样是"优化推荐算法"，在电商业务 → 商品转化率提升
- 同样是"优化推荐算法"，在直播业务 → 内容分发优化

**使用业务域特征作为推断锚点**，避免脱离业务语境做技术分类。

### 步骤3：生成候选主题

**执行**：将业务意图表述为"方向+目标"形式，提供2-3个候选供用户选择。

## 多维度验证步骤

当候选主题不确定时，从以下维度交叉验证：

| 维度 | 验证问题 |
|------|---------|
| 功能模块 | 这项工作属于产品的哪个模块？（直播间、消息、个人主页...） |
| 业务目标 | 这项工作服务于什么目标？（拉新、留存、变现、效率...） |
| 用户群体 | 这项工作影响哪类用户？（主播、观众、付费用户...） |

**执行**：三个维度的交集通常能锁定清晰主题。记录验证结果作为主题选择的依据。

## 信息不足时的处理

用户输入经常是碎片化的。处理原则：**引导补充，不要杜撰**。

### 场景1：只有版本号没有业务主题

**用户输入**："这周做了V2.19.0版本开发"

**执行**：
```
V2.19.0 这个版本主要解决什么业务问题？比如：
- 这个版本有什么核心功能或目标？
- 主要影响哪类用户？
这样我可以帮你提炼出合适的业务主题。
```

### 场景2：只有技术描述没有业务背景

**用户输入**："重构了消息队列，优化了数据库索引"

**执行**：
```
这些技术改进是为了支撑什么业务需求？比如：
- 是为了解决某个性能问题？（如消息延迟、页面加载慢）
- 还是为后续某个功能做准备？
了解业务背景后，主题会更准确。
```

### 场景3：工作过于碎片化

**用户输入**："修了几个bug，写了个文档，参加了两个会"

**执行**：
```
这些工作是围绕同一个业务方向的吗？比如：
- bug修复和文档是同一个项目的收尾工作？
- 还是分别属于不同的业务线？
如果是同一个方向，可以归纳为一个主题。
```

### 核心原则

- 拿捏得准的主题 → 直接提供，附上理由让用户确认
- 拿捏不定的主题 → 提供2-3个候选，说明各自的业务视角
- 完全缺乏信息 → 引导用户补充关键背景，而非自行臆测

## 主题命名规范

**格式**："业务方向 - 具体目标/成果"

**命名检验**：
- 管理者看到这个主题能理解你在推动什么业务？ → 合格
- 需要看正文才能理解这个主题是什么？ → 需要改进

**反例**：
- "V2.19.0开发" — 版本号对读者没有业务含义
- "日常需求" — 没有任何信息量
- "技术优化" — 过于笼统，无法判断价值

**正例**：
- "直播间商业化 - 礼物体系升级提升转化率"
- "核心链路稳定性 - 支付成功率从92%提升至99.5%"
- "新用户增长 - 邀请裂变机制上线"

## 周报主题聚焦策略

当用户一周内涉及多项工作时，**帮助用户聚焦**而非平铺所有主题。

### 聚焦 vs 平铺

**平铺做法**（避免）：
```
本周工作：
- 商业化变现 - 礼物动效优化
- 社交互动功能 - PK连麦开发
- 技术架构优化 - 数据库迁移
- 数据报表 - 周报统计建设
```
这是换了包装的任务清单。

**聚焦做法**（采用）：
执行以下步骤帮助用户聚焦：
1. 列出用户提及的所有工作事项
2. 询问："这周哪1-2项是您的重点工作，值得在周报中详细展开？"
3. 根据用户反馈选择呈现方式：
   - **单一主线**："本周聚焦礼物商业化，上线3D动效系统..."（其他工作一句话带过或不提）
   - **主次分明**："本周聚焦礼物商业化...同时配合完成PK功能需求评审...其他例行支持工作正常推进。"

### 判断重点工作的方法

一项工作值得重点展开，如果满足以下任一条件：
- 对业务指标有显著影响
- 涉及重要决策或方向转折
- 体现核心能力或突破性进展
- 涉及跨团队协作且你是主导方

### 引导用户聚焦的话术

**标准询问**：
```
您提到了几项工作：
1. 礼物动效优化（商业化方向）
2. PK功能开发（社交方向）
3. 数据报表建设（运营支持）

这周哪1-2项是您的重点工作，值得在周报中详细展开？其他工作我可以简略提及。
```

**如果用户说"都挺重要的"**：
```
如果只能让协同方记住你本周做的一件最重要的事，会是哪件？
或者说，这周的工作中，哪项对业务指标/用户体验影响最大？
```
