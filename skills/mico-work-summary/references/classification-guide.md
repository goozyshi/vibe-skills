## 一级分类：业务领域

### 1. 商业化变现

**定义**：直接影响收入的功能和优化

**典型工作**：
- 付费功能开发（会员、礼物、充值）
- 转化漏斗优化
- 定价策略调整
- 支付流程优化
- 营销活动技术支持

**主题示例**：
- 礼物体系优化
- 会员权益升级
- 支付体验改善
- 转化率提升

### 2. 社交互动功能

**定义**：用户之间的连接和互动机制

**典型工作**：
- 聊天/弹幕功能
- 关注/推荐机制
- 社交玩法（PK、连麦、匹配）
- 用户关系链建设
- 互动反馈机制

**主题示例**：
- PK连麦功能上线
- 社交推荐优化
- 用户互动体验提升
- 关系链建设

### 3. 内容生态

**定义**：内容生产、分发、消费相关

**典型工作**：
- 内容创作工具
- 内容推荐算法
- 内容审核机制
- 创作者激励体系
- 内容质量提升

**主题示例**：
- 创作者工具升级
- 内容分发优化
- 内容质量保障
- 创作者生态建设

### 4. 用户体验提升

**定义**：不直接涉及业务逻辑的体验优化

**典型工作**：
- 性能优化（加载速度、流畅度）
- 交互体验改善
- UI/视觉优化
- 无障碍支持
- 新手引导

**主题示例**：
- 性能瓶颈解决
- 交互流程优化
- 视觉体验升级
- 新手留存提升

### 5. 技术架构优化

**定义**：底层技术能力建设，支撑业务长期发展

**典型工作**：
- 系统重构
- 技术债务清理
- 架构升级
- 技术选型
- 基础设施建设

**主题示例**：
- 微服务架构迁移
- 技术债务清理
- 开发效率提升
- 技术能力储备

### 6. 稳定性保障

**定义**：确保系统可靠运行

**典型工作**：
- Bug 修复
- 监控告警
- 容灾建设
- 性能调优
- 事故处理

**主题示例**：
- 交易稳定性保障
- 核心链路可靠性提升
- 线上问题快速响应
- 监控体系完善

### 7. 运营数据增长

**定义**：直接影响增长指标的工作

**典型工作**：
- 拉新功能（邀请、裂变）
- 留存优化
- 活跃度提升
- 召回策略
- A/B 测试支持

**主题示例**：
- 用户增长机制优化
- 留存率提升
- 活跃度增长
- 召回体系建设

### 8. 合规与安全

**定义**：满足法规要求和保护用户安全

**典型工作**：
- 隐私保护
- 数据安全
- 内容审核
- 实名认证
- 合规改造

**主题示例**：
- 隐私合规改造
- 数据安全加固
- 内容风控升级
- 合规体系建设

## 二级分类：工作性质

在业务领域基础上，可进一步细化工作性质：

### A. 功能开发
- 新功能从0到1
- 示例："PK连麦功能上线"

### B. 体验优化
- 已有功能的改善
- 示例："礼物动效体验升级"

### C. 问题解决
- 修复线上问题或技术债
- 示例："支付成功率问题修复"

### D. 能力建设
- 底层能力储备
- 示例："3D渲染引擎集成"

### E. 数据驱动
- 基于数据的优化
- 示例："基于转化漏斗的流程优化"

## 使用方法

### 步骤1：识别业务实体

从用户描述中提取关键词：
- 产品功能名称（礼物、PK、充值）
- 业务指标（转化率、留存率、收入）
- 技术组件（缓存、数据库、接口）

### 步骤2：映射到业务领域

根据影响范围判断：
- 影响收入 → 商业化变现
- 影响用户互动 → 社交互动功能
- 影响性能体验 → 用户体验提升
- 影响系统稳定 → 稳定性保障
- ...

### 步骤3：确定具体方向

结合工作性质和用户目标：
- 商业化变现 + 功能开发 → "会员体系上线"
- 社交互动功能 + 体验优化 → "PK玩法优化"
- 用户体验提升 + 问题解决 → "性能瓶颈解决"

### 步骤4：形成主题命名

格式："业务领域 - 具体方向"

示例：
- "商业化变现 - 礼物转化率提升"
- "社交互动功能 - PK连麦上线"
- "稳定性保障 - 支付成功率优化"

## 边界案例判断

### 案例1：技术重构 vs 业务优化

**问**：重构了用户数据访问层，应该归类为"技术架构优化"还是"用户体验提升"？

**判断标准**：看最终影响
- 如果重构后用户可感知（性能提升、功能增强）→ 用户体验提升
- 如果重构仅改善内部结构，用户无感知 → 技术架构优化

### 案例2：Bug修复 vs 功能开发

**问**：修复了支付回调问题，应该归类为"稳定性保障"还是"商业化变现"？

**判断标准**：看问题严重程度和影响范围
- 如果是影响大量用户的线上问题 → 稳定性保障
- 如果是小范围影响或预防性优化 → 归入主要业务线（商业化变现）

### 案例3：多领域交叉

**问**：上线了会员专属礼物，涉及商业化和社交互动，如何分类？

**判断标准**：看核心目标
- 询问用户：这项工作的主要目的是什么？
- 提升会员收入 → 商业化变现 - 会员权益升级
- 增强互动体验 → 社交互动功能 - 礼物体系升级

## 分类不确定时的处理

当无法明确分类时：
1. 提供2-3个候选主题
2. 说明每个主题对应的业务视角
3. 让用户根据实际目标选择

示例：
```
您提到的"优化直播间礼物动效"，可以从不同角度理解：

1. 商业化变现 - 礼物转化率提升
   视角：通过更炫酷的动效吸引用户送礼

2. 用户体验提升 - 视觉反馈优化
   视角：改善互动反馈，提升观看体验

3. 技术能力建设 - 渲染性能优化
   视角：提升动效渲染能力，为后续功能打基础

请选择最符合本周工作重点的主题。
```
