# 工作主题提炼方法论

本文档指导如何从具体工作事项中提炼抽象的业务主题。

## 核心原则

**提炼主题 ≠ 分类标签**

主题提炼是一个**推理过程**，而非查表匹配。需要理解：
1. 这项工作**影响了什么**（业务目标）
2. 这项工作**为什么重要**（背后的价值）
3. 这项工作**解决了什么问题**（上下文）

## 提炼框架：三层提问法

### 第一层：识别影响范围

通过提问引导推理：

**问题1：这项工作最终影响了谁？**
- 直接影响用户 → 可能是体验类/功能类主题
- 直接影响收入 → 可能是商业化主题
- 直接影响开发者 → 可能是基础设施主题
- 直接影响系统稳定性 → 可能是保障类主题

**问题2：如果这项工作没做，会发生什么？**
- 用户流失 → 留存/体验相关
- 收入下降 → 变现相关
- 系统宕机 → 稳定性相关
- 开发效率低 → 效能相关

### 第二层：提炼核心价值

**问题3：这项工作的本质目标是什么？**

用"为了..."句式追问：
- "做了礼物动效" → **为了**提升用户送礼意愿 → 商业化变现
- "做了PK连麦" → **为了**增加用户互动时长 → 社交互动 / 用户留存
- "重构了缓存层" → **为了**支撑更大流量 → 技术能力储备 / 稳定性保障

**关键判断**：当目标有多个时，选择**最直接的业务影响**。

### 第三层：确定主题方向

基于前两层推理，形成主题假设，并**提供选项让用户确认**。

**模板格式**：
```
根据您提到的"[具体工作]"，这项工作可能属于：

1. [主题方向A] - [具体描述]
   理由：[为什么这样理解]

2. [主题方向B] - [具体描述]
   理由：[为什么这样理解]

3. [主题方向C] - [具体描述]
   理由：[为什么这样理解]

请选择最符合本周工作重点的主题，或补充说明实际目标。
```

## 常见推理路径示例

### 示例1：技术实现 → 业务主题

**用户输入**："优化了直播间礼物动效渲染性能"

**推理过程**：
1. 识别影响：礼物是付费功能，动效影响用户送礼体验
2. 提炼价值：性能优化 → 动效更流畅 → 用户更愿意送礼
3. 形成选项：
   - 商业化变现 - 礼物转化体验优化（强调收入影响）
   - 用户体验提升 - 视觉交互流畅度优化（强调体验影响）
   - 技术能力建设 - 渲染引擎性能提升（强调技术储备）

**引导用户选择**：询问"这项工作的主要驱动因素是什么？"

### 示例2：多目标交叉 → 明确优先级

**用户输入**："上线了会员专属礼物"

**推理过程**：
1. 识别影响：既影响会员收入，又影响礼物收入，还涉及社交互动
2. 提炼价值：核心目标是什么？
   - 如果是提升会员订阅量 → 商业化变现 - 会员权益升级
   - 如果是提升礼物流水 → 商业化变现 - 礼物体系优化
   - 如果是增强身份标识 → 社交互动功能 - 用户身份体系
3. 形成选项并询问："这个功能上线后，团队最关注哪个数据指标？"

### 示例3：问题修复 → 判断性质

**用户输入**："修复了支付回调超时问题"

**推理过程**：
1. 识别影响：支付是核心链路，影响收入和用户体验
2. 判断严重性：
   - 如果影响大量用户 → 稳定性保障 - 核心链路可靠性
   - 如果是预防性优化 → 商业化变现 - 支付体验优化
3. 形成选项并询问："这个问题影响了多少用户？是线上紧急修复还是日常优化？"

## 常见抽象维度参考

以下维度**仅作为思考参考**，不是固定分类列表。实际使用时应根据业务上下文灵活推理。

### 按影响对象分类
- 影响用户 → 体验类/功能类
- 影响收入 → 商业化类
- 影响开发 → 效能类
- 影响系统 → 稳定性类

### 按工作性质分类
- 从0到1 → 功能开发
- 从1到N → 体验优化/能力建设
- 修复问题 → 问题解决/稳定性保障
- 数据驱动 → 增长优化/转化提升

### 按业务领域分类（示例，非穷举）
- 商业化变现（直接影响收入）
- 社交互动功能（用户连接与互动）
- 内容生态（内容生产与分发）
- 用户体验提升（性能与交互）
- 技术架构优化（底层能力建设）
- 稳定性保障（系统可靠性）
- 运营数据增长（拉新留存活跃）
- 合规与安全（法规与风控）

## 边界案例处理

### 案例：技术重构的业务价值

**场景**：重构了用户数据访问层

**推理路径**：
1. 追问用户感知：用户能直接感受到变化吗？
   - 能（性能提升、功能增强）→ 用户体验提升
   - 不能（仅内部结构优化）→ 技术架构优化
2. 追问业务目标：这次重构的驱动因素是什么？
   - 支撑新功能开发 → 技术能力建设
   - 解决性能瓶颈 → 稳定性保障 / 用户体验提升

### 案例：跨领域工作的主题选择

**场景**：上线了会员专属礼物动效

**推理路径**：
1. 列出所有影响维度：会员订阅、礼物收入、社交互动、视觉体验
2. 询问用户核心目标："这个功能的主要 KPI 是什么？"
3. 根据回答确定主题：
   - 会员订阅量 → 商业化变现 - 会员权益升级
   - 礼物流水 → 商业化变现 - 礼物体系优化
   - 用户互动时长 → 社交互动功能 - 互动体验提升

## 提炼主题的反模式

### ❌ 错误示范1：直接使用技术实现

> "本周工作主题：实现了 WebGL 礼物动效渲染"

**问题**：陷入技术细节，缺少业务价值

**正确做法**：提炼为"商业化变现 - 礼物转化体验优化"，技术实现作为支撑细节

### ❌ 错误示范2：过于宽泛

> "本周工作主题：优化用户体验"

**问题**：主题过于笼统，无法体现具体价值

**正确做法**：明确具体方向，如"用户体验提升 - 首屏加载性能优化"

### ❌ 错误示范3：机械匹配分类

> "因为涉及礼物，所以是商业化变现"

**问题**：忽略实际业务目标，生搬硬套

**正确做法**：基于工作的实际影响和目标进行推理，而非关键词匹配

## 使用建议

1. **优先询问而非断言**：当主题不明确时，提供 2-3 个选项让用户确认
2. **说明推理依据**：解释为什么提供这些选项，帮助用户理解差异
3. **关注业务价值**：始终追问"为了什么"，而非停留在"做了什么"
4. **灵活调整颗粒度**：根据工作复杂度调整主题抽象程度
