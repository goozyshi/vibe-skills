## 自评与年度总结的关系

**年度工作总结 (summary.md)**：
- 面向协同方（产品、运营、合作团队）
- 聚焦"做成了什么"
- 基于工作事实的重点产出整理
- 公开信息，避免敏感数据

**员工自评 (self.md)**：
- 面向评审方（上级、HR）
- 聚焦"做得怎么样"
- 基于岗位预期的自我评价与复盘
- 可包含敏感数据和内部信息

**两者的互补关系**：
- 年度总结重事实陈述，自评重评价判断
- 年度总结展示产出，自评展示成长和反思
- 年度总结用公开数据,自评可补充敏感数据

## 自评结构

### 第一部分：核心业绩与工作思考

这部分与年度工作总结形成互补，有两种使用方式：

**方式A：补充敏感数据**（当年度总结因信息公开限制无法详述时）

```markdown
## 核心业绩

本部分补充年度工作总结中因信息敏感度限制未详细展开的关键数据：

### 商业化变现核心数据
- 礼物收入从Q1的180万/月增长至Q4的360万/月，翻倍增长
- 大R用户(月消费>1000元)占比从8%提升到15%
- 付费转化率从2.3%提升到3.8%

[继续展开其他敏感但对评审重要的信息]
```

**方式B：展开工作思考**（当年度总结聚焦产出，此处补充思考深度）

```markdown
## 全年工作思考

### 战略打法
全年围绕"提升单用户价值"这一核心目标，采取了三阶段策略：
- Q1-Q2：建基础（礼物体系、支付链路）
- Q2-Q3：提转化（优化漏斗、降低门槛）
- Q3-Q4：做分层（会员体系、差异化权益）

这一策略调整源于Q1数据分析，发现...

### 关键举措
在执行过程中，有两个决策对最终结果影响显著：
1. [决策1]：为什么做这个决策？当时有哪些考量？
2. [决策2]：这个决策如何改变了后续方向？

### 收获沉淀
通过全年实践，形成了以下可复用的方法论：
- [方法论1]：适用场景、核心要点
- [方法论2]：实践经验、注意事项
```

**选择建议**：
- 如果年度总结已经详细展开了背景和思考，此处用方式A补充数据
- 如果年度总结因篇幅限制聚焦产出，此处用方式B展开思考深度
- 两种方式可混合使用

### 第二部分：个人复盘

这是自评的核心部分，基于岗位预期进行自我评估。

#### 2.1 对比预期

**目标**：说明实际结果与年初预期的差异

**撰写方法**：
- 回顾年初设定的目标（如果有OKR，直接引用）
- 对比实际达成情况
- 分析超出或未达预期的原因

**结构模板**：
```markdown
## 对比预期

年初设定的核心目标：
1. [目标1]：预期XX，实际达成YY
2. [目标2]：预期AA，实际达成BB

### 超出预期的部分
[目标1] 实际达成YY，超出预期Z%

主要原因：
- [原因1]：具体发生了什么？
- [原因2]：哪些因素起了关键作用？

### 未达预期的部分
[目标2] 实际达成BB，与预期差距X%

主要原因：
- 客观因素：[外部环境变化、资源限制等]
- 主观因素：[自身能力短板、判断失误等]

调整措施：
- [已采取的改进行动]
- [后续计划]
```

**示例**：
```markdown
年初目标：将用户留存率从45%提升到55%

实际达成：52%（达成70%）

未完全达成的原因：
- 客观因素：Q2竞品密集推出新功能，分流了部分用户
- 主观因素：对新用户流失原因的分析不够深入，Q1-Q2的优化方向偏了

Q3及时调整：
- 重新做了流失用户调研，发现核心问题是新手引导不清晰
- Q3-Q4聚焦新手体验优化，单季度留存率提升7个百分点
```

#### 2.2 未来发展

**目标**：针对需要提升的部分，说明改进方向

**撰写方法**：
- 识别当前能力短板或待提升领域
- 说明为什么需要提升（对业务或个人发展的价值）
- 制定具体的改进计划

**结构模板**：
```markdown
## 未来发展

### 待提升领域1：[能力/领域名称]

现状：
- [当前水平描述]
- [遇到的瓶颈或不足]

提升价值：
- 对业务：[能解决什么问题/创造什么价值]
- 对个人：[能力成长方向]

改进计划：
- 短期（Q1）：[具体行动]
- 中期（上半年）：[阶段目标]
- 长期（全年）：[期望达到的状态]
```

**示例**：
```markdown
### 待提升领域：数据驱动决策能力

现状：
- 能使用基础数据指标（DAU、留存率）评估效果
- 但缺乏主动通过数据发现问题、验证假设的能力
- 在项目早期依赖产品/运营的数据分析，自己较少深入挖掘

提升价值：
- 对业务：能更早发现潜在风险，更快验证优化方向
- 对个人：从"执行者"向"决策者"转变的关键能力

改进计划：
- Q1：学习SQL和基础数据分析方法，能独立查询和分析核心指标
- Q2：在新项目中主动建立数据埋点和监控体系
- 下半年：尝试通过数据主动发现至少2个优化机会并推动落地
```

#### 2.3 成功经验

**目标**：提炼可复制的方法论

**撰写方法**：
- 回顾全年做得好的部分
- 分析为什么能做好（方法、思路、习惯）
- 总结成可在未来复用的方法论

**结构模板**：
```markdown
## 成功经验

### 经验1：[方法论标题]

应用场景：
- [在哪些工作中使用了这个方法]

核心做法：
- [具体是怎么做的]
- [关键步骤或要点]

效果验证：
- [带来了什么结果]
- [如何证明这个方法有效]

可复用性：
- [适用于哪些类似场景]
- [需要注意的前提条件]
```

**示例**：
```markdown
### 经验1：灰度验证 + 快速迭代

应用场景：
在礼物动效优化、PK玩法调整等多个项目中使用

核心做法：
1. 小流量灰度（5%-10%）先验证核心指标
2. 基于数据快速决策：
   - 指标正向 → 扩量到50%，继续观察
   - 指标负向 → 立即回滚，分析原因后再试
3. 全量前至少经历2轮灰度验证

效果验证：
- 避免了3次可能的线上事故（灰度阶段发现问题及时止损）
- 成功迭代的项目平均上线周期从4周缩短到2周

可复用性：
- 适用于有一定用户量、允许分流的功能优化
- 前提是有完善的灰度能力和实时监控
```

#### 2.4 根因分析

**目标**：深挖未达成部分的原因，明确改进方向

**撰写方法**：
- 选择1-2个最重要的未达成目标
- 区分主观原因（自身可控）和客观原因（外部因素）
- 针对主观原因制定改进措施

**结构模板**：
```markdown
## 根因分析

### 未达成项：[目标描述]

表象原因：
- [直接导致未达成的现象]

深层原因：
**客观因素**（外部不可控）：
- [原因1]：具体是什么情况？
- [原因2]：...

**主观因素**（自身可改进）：
- [原因1]：为什么会这样？哪个环节出了问题?
- [原因2]：...

改进措施：
- 针对主观原因1：[具体改进行动]
- 针对主观原因2：[具体改进行动]

验证方式：
- [如何验证改进措施有效？]
```

**示例**：
```markdown
### 未达成项：技术架构重构（原计划Q3完成，实际延期至Q4）

表象原因：
- Q2需求评估不准确，低估了迁移成本
- Q3中途发现兼容性问题，返工2周

深层原因：
**客观因素**：
- Q3突然插入紧急需求，占用了20%的人力

**主观因素**：
- 前期调研不充分，对老系统依赖理解不深入
- 风险预案不足，遇到问题时决策缓慢
- 没有及时同步进度，导致协作方安排被打乱

改进措施：
- 后续大型重构项目先做为期1周的技术预研，输出详细的风险清单
- 建立周度同步机制，提前暴露风险而非临近deadline才发现
- 提升项目管理能力，学习如何拆分里程碑、控制节奏

验证方式：
- 下次类似项目进度偏差控制在10%以内
- 在季度复盘时收集协作方反馈
```

### 第三部分：价值观（可选）

**适用情况**：
- 公司有明确的价值观体系
- 绩效评估包含价值观维度
- 有具体的价值观践行案例可分享

**撰写原则**：
- 不要面面俱到，选择1-2个最相关的价值观
- 必须结合具体行为案例，避免空泛表态
- 说明这个价值观如何影响了决策或行动

**详细参考**：请查阅 `references/values-framework.md`，其中包含：
- 四大价值观详解（正念、极端、简单、谦卑）
- 每个价值观的行为准则和践行场景示例
- 价值观撰写模板和常见误区

**快速指引**：

| 价值观 | 典型冲突场景 | 践行表现 |
|-------|-----------|---------|
| 正念 Do Right | 短期利益 vs 长期价值 | 拒绝投机，坚持对的事 |
| 极端 Push Beyond | 完成任务 vs 追求极致 | 不满足现状，突破边界 |
| 简单 Stay Simple | 复杂流程 vs 高效决策 | 化繁为简，直接有效 |
| 谦卑 Stay Humble | 坚持己见 vs 接纳意见 | 虚心学习，开放协作 |

### 第四部分：管理自评（仅 Leader，可选）

**适用对象**：带团队的 Leader（TL、Manager、Director）

**目标**：评估管理工作的有效性

**详细参考**：请查阅 `references/leadership-framework.md`，其中包含：
- 三大管理维度详解（管好业务、带好团队、传好文化）
- 每个维度的评估标准和自评模板
- 丰富的管理场景示例和撰写指南

**三个管理维度概览**：

| 维度 | 核心关注 | 一句话释义 |
|-----|---------|-----------|
| **管好业务** | 目标达成、策略有效性 | 制定明确目标和清晰策略，带领团队解决问题并实现目标 |
| **带好团队** | 人才培养、团队氛围 | 组建高效团队，识别优劣势，帮助成员发挥潜力 |
| **传好文化** | 价值观践行、文化传递 | 以身作则传递价值观，营造向上奋进的工作环境 |

**快速指引**：

每个维度建议包含：
- **现状描述**：团队/业务的客观状态
- **具体案例**：做得好的和待提升的具体事例
- **深度反思**：为什么成功？为什么失败？
- **改进计划**：后续如何提升

## 自评写作检查清单

完成初稿后，逐项检查：

**内容完整性**：
- [ ] 核心业绩部分是否与年度总结形成了有效互补？
- [ ] 个人复盘是否覆盖了对比预期、未来发展、成功经验、根因分析？
- [ ] 价值观部分是否结合了具体案例（而非空泛表态）？
- [ ] 管理自评（如适用）是否覆盖了三个维度？

**深度与诚恳**：
- [ ] 是否真实反映了自己的不足（而非只说优点）？
- [ ] 根因分析是否深入到主观原因（而非只归咎客观因素）？
- [ ] 改进措施是否具体可执行（而非"继续努力"之类空话）？

**语言表达**：
- [ ] 是否避免了假大空的表述？
- [ ] 是否提供了具体案例支撑观点？
- [ ] 是否保持了客观冷静的反思态度（而非过度自我批判或自夸）？

**信息适度**：
- [ ] 敏感数据是否标注了保密级别？
- [ ] 是否有不适合写入的内容（如对他人的负面评价）？

## 常见误区

**误区1：避重就轻，只说成绩不说问题**
- 自评的价值在于展示自我认知和成长潜力
- 合理暴露不足反而体现成熟度

**误区2：过度自我批判，放大问题**
- 客观描述问题和原因，不需要情绪化表达
- 关注可改进的部分，而非纠结无法改变的结果

**误区3：价值观部分空泛表态**
- "我始终践行XX价值观" → 无效
- "在XX场景下，我选择了XX，因为..." → 有效

**误区4：管理自评只说团队成绩**
- 团队成绩应该在年度总结中展示
- 自评聚焦管理有效性：如何带人、如何决策、如何改进

**误区5：改进措施模糊不可执行**
- "提升技术能力" → 无效
- "Q1学习XX技术，Q2在项目中实践" → 有效
