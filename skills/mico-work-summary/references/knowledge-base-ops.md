## 知识库结构

```markdown
## <业务名称>
类型: <业务类型>
核心特性: [<特性1>, <特性2>, <特性3>]
历史主题:
  <YYYY-MM>: [主题1, 主题2, ...]
  <YYYY-MM>: [主题1, ...]
```

**示例**：
```markdown
## MicoWorld
类型: 出海社交视频直播App
核心特性: [实时互动, 虚拟礼物, 主播PK]
历史主题:
  2025-03: [商业化变现-礼物动效, 社交互动功能-PK连麦]
```

## 读取业务信息

**适用场景**：新建报告、迭代更新、跨周期汇总

**执行步骤**：
1. 从用户输入中提取业务名称（如"MicoWorld"、"SoulStar"）
2. 检查 `~/mico-work-summary/.knowledge/business-knowledge.md` 是否存在该业务
3. 若存在：读取业务类型、核心特性、历史主题列表
4. 若不存在：跳转到[创建新业务条目](#创建新业务条目)

**输出**：业务域特征（类型+特性+历史主题）或"业务不存在"标记

---

## 创建新业务条目

**适用场景**：首次提及某个业务时

**执行步骤**：
1. 询问用户业务背景：
   - "这是什么类型的业务？"（如：出海社交视频直播App）
   - "核心业务模式/特性是什么？"（如：通过虚拟礼物和会员变现）

2. 按以下格式创建新条目并追加到知识库：
   ```markdown
   ## <业务名称>
   类型: <业务类型>
   核心特性: [<特性1>, <特性2>, <特性3>]
   历史主题:
     <YYYY-MM>: []
   ```

3. 记录当前月份，为后续主题记录做准备

**重要**：使用**追加模式**写入，禁止覆盖已有内容。

---

## 更新历史主题

**适用场景**：报告生成/更新完成后

**执行步骤**：
1. 获取本次报告确定的工作主题列表
2. 定位该业务的历史主题记录（按YYYY-MM查找）
3. 追加本次主题到对应月份列表

**追加格式**：
```markdown
历史主题:
  2025-03: [原有主题, 新增主题1, 新增主题2]  # 追加到已有月份
  2025-04: [新主题]  # 或创建新月份条目
```

**约束**：
- 相同主题不重复记录（检查语义相似度）
- 主题表述需与报告中保持一致

---

## 更新核心特性

**适用场景**：发现新的业务维度时（不常见）

**执行步骤**：
1. 识别新的特性维度（如业务新增"社区内容"模块）
2. 更新核心特性列表：
   ```markdown
   # 原
   核心特性: [实时互动, 虚拟礼物]
   
   # 更新后
   核心特性: [实时互动, 虚拟礼物, 社区内容]
   ```

**触发条件**：仅当发现全新业务维度时，不用于日常迭代。

---

## 并发安全原则

**写入原则**：
- 始终使用追加模式（append）
- 禁止覆盖（overwrite）已有条目
- 如需修正，先读取全文，修改后整体更新

**读取原则**：
- 单用户单会话，无需加锁
- 每次操作前重新读取，避免使用缓存
